# v0.2 独立复核：T1—T3

日期：2026-09-16。只读正文，未修改章节。通读 T1—T3，并定点核对 μTransfer、Chinchilla、DoReMi、RegMix、FineWeb、Dolma、Llama 3、DeepSeekMoE、Fine-Grained MoE、MLA 与数据供给预测原文。未重跑实验。未发现会推翻三个章节主线的错误；有以下两处影响比较条件或复核的定义需要补齐。

## 1. [P2] 共享专家必须从激活路由预算中扣除

位置：[T3 第 2 节](../docs/03-architecture-deployment.md)，目前第 21、25–30 行。

正文先把每 token 调用数扩大为 $mk$，再增加始终激活的共享专家，公式中的 TopK 又未定义 K，也未说明路由候选与共享集合互斥。读者据此实现，可能得到 $mk+|S|$ 个激活专家，破坏本段强调的相同激活计算比较。

原文 §3.2、式 (9)–(11) 明确：从已有细粒度专家中隔离 $K_s$ 个共享专家；其余路由候选为 $mE-K_s$ 个，每 token 只再选 $mk-K_s$ 个，总激活仍为 $mk$。建议正文补一句，并将公式的路由集合限定为非共享专家、TopK 的大小限定为 $mk-|S|$。这不改变论点，却是成本对照成立的必要条件。[DeepSeekMoE v1](https://arxiv.org/html/2401.06066v1)

## 2. [P2] Chinchilla 的“不足一个 epoch”应限定为规模律拟合实验

位置：[T2 第 1 节](../docs/02-data.md)，目前第 9 行。

“Chinchilla 的主要实验不足一个 epoch”容易同时覆盖最终 70B、1.4T token 模型。原文 §5 所说的是用于 analysis 的训练 runs；附录 A、表 A1 则明确最终 1.4T token 配方中 MassiveWeb 为 1.24 epoch、Wikipedia 为 3.40 epoch。建议改为“用于规模律分析的训练 runs 主要处于不足一轮的数据区间；最终模型的个别子域已有重复”，再保留“未系统解决数据受限下多轮训练”的结论。否则本章以重复与混合为核心变量，却把子域重复边界抹平了。[Chinchilla v1，§5、附录 A](https://arxiv.org/html/2203.15556v1)

## 已核对且无需纠错的重点

- Chinchilla 最优指数推导与 overtraining 的 $L(C,M)$ 改写，代数方向一致。
- μTransfer 的 40M→6.7B、7% 调参预算和 FP32／FP16、位置编码混杂，均能对应 §7.4。
- DoReMi 的约 6.5 个百分点、8% 额外 FLOPs，以及 RegMix 的 512 个小代理、非 embedding 参数口径和约 2% 估计 FLOPs，均与原文一致。
- Llama 3 的约 402B／16.55T 外推与最终 405B，原文 §3.2.1 支持。
- FineWeb 的教育领域与广泛网页领域差异、Dolma 多种过滤器叠加减少可用数据的说法，均有原文依据。FineWeb 的 Paloma 分域困惑度比较未去污染，当前正文将其用于“覆盖／拟合差异”而非独立泛化证明，这一界限应保留。
- FlashAttention 在线 softmax 合并式、标准 KV 存储账式与 MLA 缓存形状未发现代数或量纲问题。
